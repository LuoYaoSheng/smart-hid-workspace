TUTORIAL · 5 分钟跑通

快速开始

从烧录固件到发出第一条 HID 命令。完成后，任何能发 HTTP 请求的程序都能驱动你的电脑键鼠。

概览

本教程走完这条链路的最小闭环：

ESP32-S3 烧录→ 启动 ControlHub→ 小程序配网配对→ HTTP 下发命令
全程纯本地。ControlHub 内嵌 MQTT Broker，控制指令不经过互联网，也不需要云端账号。

1. 准备

硬件ESP32-S3 开发板（带 USB，8MB Flash）+ 一根数据线 + 一台目标电脑（USB 口）
软件从 下载区 取：controlhub（你的平台）+ 固件烧录包
工具esptool（pip install esptool）、Python 3
配网手机装 BLE Toolkit+ 微信小程序（搜索附近 Smart HID 用）

2. 烧录固件

把 ESP32-S3 用 USB 接到电脑，运行烧录脚本：

cd downloads/firmware
pip install esptool            # 首次需要
./flash.sh                     # 自动探测串口；或 ./flash.sh /dev/ttyUSB0

看到 Hash of data verified 和 Hard resetting via RTS pin... 即成功。设备重启后状态 LED 亮起。

串口名：Linux 多为 /dev/ttyUSB0，macOS 为 /dev/cu.usbmodem*，Windows 为 COM3 等（设备管理器查）。

3. 启动 ControlHub

解压并运行你平台对应的二进制：

# macOS（Apple Silicon）
chmod +x controlhub-darwin-arm64
./controlhub-darwin-arm64

# Windows
controlhub-windows-amd64.exe

首次启动会生成 API Key（前缀 chk_），只写入 data/initial-api-key.txt（不进日志）：

cat data/initial-api-key.txt
chk_a1b2c3d4e5f6...      ← 记下后删除该文件

健康检查（无需鉴权）：

curl http://127.0.0.1:17890/api/v1/health
# {"status":"ok", ...}

4. 配网配对

  1. 手机打开 BLE Toolkit+ 小程序，进入 HID Tab，点 搜索 Smart HID。
  2. 选到你的设备（广播名 SHID-XXXXXX），BLE 连接后读取 Device Info。
  3. 按引导配 Wi-Fi（设备需连入与 ControlHub 同一局域网）。
  4. 扫描 ControlHub 配对码（ControlHub Web 控制台或日志里的 QR），完成配对。
  5. 设备状态变为 online · usb_hid_ready。

验证设备已上线：

curl -H "Authorization: Bearer chk_a1b2c3d4e5f6..." \
     http://127.0.0.1:17890/api/v1/devices

5. 第一条命令

给目标电脑发一次回车（把目标电脑用 USB 接到 ESP32-S3 的 HID 输出口）：

curl -X POST http://127.0.0.1:17890/api/v1/devices/HID-A1B2C3D4/commands \
  -H "Authorization: Bearer chk_a1b2c3d4e5f6..." \
  -H "Content-Type: application/json" \
  -d '{
    "protocol": "1.0",
    "request_id": "req-001",
    "device_id": "HID-A1B2C3D4",
    "type": "keyboard",
    "action": "tap",
    "ttl_ms": 3000,
    "payload": { "key": "ENTER" }
  }'

同步响应（命令已派发）：

{ "accepted": true, "request_id": "req-001", "device_id": "HID-A1B2C3D4" }

查询执行结果（ACK 落库后）：

curl -H "Authorization: Bearer chk_..." \
     http://127.0.0.1:17890/api/v1/commands/req-001
# { "status": "executed", "code": 0, "execution_ms": 42 }
✅ 目标电脑光标处收到一次回车。完整字段与状态机见 API 文档。

6. Web 控制台（可选）

不想敲 curl？ControlHub 自带本地 Web 控制台：

浏览器打开  http://127.0.0.1:17890/

顶部填入 API Key → 在命令编辑器里选「键盘 / tap / ENTER」→ 发送。设备表实时刷新在线状态。

7. 演示：网页模拟键鼠（强烈推荐）

想直观看效果？用另一台电脑（B）的浏览器遥控这台电脑（A）：

  1. A 电脑：打开 Web 控制台 http://127.0.0.1:17890/ → 设置区开启 LAN 模式 → 按提示重启 ControlHub
  2. B 电脑：浏览器打开 http://<A 的局域网 IP>:17890/demo.html（同 Wi-Fi/网段）
  3. 填入 API Key → 选择设备 → 开始：点可视化键盘打字、拖触控板移动 A 电脑光标、或用 B 的实体键盘直通输入——A 电脑收到的是真实键鼠输入，打开记事本即可看到逐字打出

页面顶部实时显示往返延迟与 executed 计数；⚡ 实时通道指示灯亮起后，事件流面板实时推送设备状态与命令回执——第二块屏幕打开同一页面即可实时观战；⛔ 释放所有按键随时急停（演示的正是系统的可靠性语义：lease 兜底 + release_all）。

这些服务都可在 config.yaml 里开关与改端口（演示台 web.demo、控制台 web.console、实时通道 web.realtime、API http.enable_api、配对端口 pairing.port），详见仓库 README 的「配置参考」。

排错

设备一直是 offline / unknown

Wi-Fi 没配成功，或与 ControlHub 不在同一网段。回小程序 诊断 页查 Wi-Fi / ControlHub 连接项。ControlHub 默认只监听 127.0.0.1，要让设备从局域网连 MQTT，需在 config.yaml 显式开启 LAN 监听。

设备 online 但 usb_hid_ready=false

ESP32-S3 的 HID 输出未接到目标电脑，或目标电脑未枚举出 USB 键鼠。检查 USB 线（必须数据线）和目标电脑设备管理器。

命令返回 401

API Key 不对。首次启动的 Key 在 data/initial-api-key.txt；也可以在 config.yaml 的 api_key 固定一个，或用 POST /api/v1/api-keys/rotate 轮换。

命令返回 expired

ttl_ms 内未执行完（设备忙或离线）。调大 ttl_ms，或检查设备是否 usb_hid_ready。
